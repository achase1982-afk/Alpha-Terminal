3. DETERMINISTIC REJECTION LAYER & PORTFOLIO LOGIC
--------------------------------------------------

Implement a pure backend function, something like:

validateAiLabIdea(candidate: TradeIdea, activeIdeas: TradeIdea[], marketDataSnapshot: {...}): {
  approved: boolean
  rejectionReason?: string
}

Rules (hard constraints):

Liquidity / tradability (for options):

- If instrumentType includes OPTIONS:
  - If entrySpreadPct > 0.10 (10%), reject with "WIDE_SPREAD".
  - If oiAtEntry < 500 on any primary leg, reject with "LOW_OI".
  - If volumeToOiRatio < 0.10, reject with "LOW_ACTIVITY".
  - If dte < 5 (for non-index weeklies), reject with "DTE_TOO_SHORT" (configurable).

For stock-only ideas:
- If avgVolume20d < some threshold (e.g., 500k), reject "LOW_LIQUIDITY".

Portfolio constraints (using activeIdeas):

- If activeIdeas.length >= 5 → reject with "MAX_ACTIVE_REACHED" (for now; in later phases we may replace weakest idea).
- Count by sector:
  - If adding this idea would make >3 active ideas in same sector → reject "SECTOR_CONCENTRATION".
- Count by direction:
  - If adding this idea would make >4 active longs or >4 active shorts → reject "DIRECTION_SKEW".
- Correlation check:
  - Assume we have a daily 20d correlation matrix service (you can stub a function getCorrelation(symbolA, symbolB)).
  - If new idea has correlation > 0.8 with an existing ACTIVE idea in same direction, reject "HIGH_CORRELATION_DUPLICATE".

Idea duplication/contradiction:

- If an ACTIVE idea already exists on same symbol & same direction & similar structure, reject "DUPLICATE_IDEA".
- If an ACTIVE idea exists on same symbol & opposite direction, reject "CONTRADICTORY_IDEA".

Data sanity:

- If marketDataSnapshot shows stale data (e.g., dataFreshnessMinutes > some threshold) for key inputs, reject "STALE_DATA".

This function should NOT:
- Call any LLMs.
- Touch UI.
- It should be deterministic and fully testable in isolation.
