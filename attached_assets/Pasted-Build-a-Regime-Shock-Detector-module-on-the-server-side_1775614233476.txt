Build a Regime Shock Detector module on the server side. This system detects sudden market dislocations where multiple indicators move sharply in the same direction within a short window, suggesting a structural break rather than normal volatility. It runs inside the existing Market Pulse scoring cycle, not as a separate loop. After the scoring engine computes indicator values but before finalizing the composite score, it checks the regime shock trigger conditions. Here are the trigger conditions. Any 3 of these firing within a 30-minute window declares a regime shock. Trigger 1: VIX percent change from prior close exceeds plus or minus 20 percent. Trigger 2: /ES percent change from prior close exceeds plus or minus 2 percent. Trigger 3: Credit spread widening, calculated as HYG minus IEF spread widening more than 1.5 standard deviations from its 20-day mean. Trigger 4: SKEW drops more than 10 points from prior close (skip this trigger if SKEW data is unavailable). Trigger 5: Breadth flip, defined as NYSE advance-decline line (ADD) reversing sign from the prior reading AND NASDAQ advance-decline (ADD/Q) also reversing sign in the same direction within the same scoring cycle. Trigger 6: Put-call ratio spike, defined as PCSPY exceeding 2 standard deviations above its 20-day mean. Use PCSPY since CPC/CPCE/CPCI may have data issues. The state machine has four states. NORMAL is the default. When 2 triggers fire within a 30-minute window, transition to REGIME_SHOCK_WARNING. When a 3rd trigger fires within that same 30-minute window, transition to REGIME_SHOCK_ACTIVE. If the 30-minute window expires without a 3rd trigger, revert to NORMAL. When triggers subside below threshold while in ACTIVE, transition to REGIME_SHOCK_COOLING. When all triggers have been clear for 60 continuous minutes while in COOLING, transition back to NORMAL. Store the trigger state in memory on the server. Track which triggers are active and their timestamps. Use a 30-minute sliding window. Expose the current shock state as a field in the Market Pulse SSE response so the frontend can read it from the existing data stream without a new endpoint. The field should include shockState (NORMAL, WARNING, ACTIVE, COOLING), activeTriggers (array of which triggers are firing), and shockActivatedAt (timestamp, null if NORMAL). When REGIME_SHOCK_ACTIVE is first entered, send a single push notification to the user: “Regime shock detected. Multiple indicators in extreme dislocation. Normal scanning paused.” When transitioning from COOLING back to NORMAL, send a single push notification: “Regime shock cleared. Normal scanning resumed.” The Market Pulse narrative from Claude should prepend a warning when shock is ACTIVE or WARNING. Pass the shockState into the narrative prompt context so Claude can reference it. Add a shockActive boolean that the Scanner tab and Strategist tab can check. When shockActive is true, the Scanner should display a message like “Scanning paused: regime shock active” instead of results. The Strategist should only offer Mode 4 hedging and defensive recommendations when shockActive is true. On the frontend, add a visual indicator when shock state is WARNING or ACTIVE. A small banner or badge near the bias strip is fine. Use yellow for WARNING and red for ACTIVE. Do not add a new page or tab for this. For the 20-day standard deviation calculations on credit spreads and put-call ratio, compute a rolling 20-day mean and standard deviation from the historical values stored in the scoring engine. If 20 days of history is not yet available, use whatever history exists with a minimum of 5 days, and widen the trigger threshold to 2.0 standard deviations until 20 days of data accumulates. Do not create any new API endpoints. Do not modify the Market Pulse scoring weights or cluster definitions. Do not modify the indicator list. This module only reads indicator values that the scoring engine already computes and adds the shock detection layer on top.​​​​​​​​​​​​​​​​
