Task 4: Protect the WebSocket Server.

- Modify the WebSocket server initialization to use `noServer: true`.
- Intercept the HTTP upgrade in `server.on('upgrade', async (req, socket, head) => {...})`.
- Extract the Clerk session token from the query string: `?clerk_token=<token>`.
- Verify the token server-side using `createClerkClient({ secretKey }).verifyToken(token)`.
- If invalid or missing: `socket.write('HTTP/1.1 401 Unauthorized\r\n\r\n'); socket.destroy(); return;`
- If valid: call `wss.handleUpgrade(req, socket, head, (ws) => { wss.emit('connection', ws, req); })`.
- Do NOT use the Authorization header approach for WebSocket; browser WebSocket API cannot set custom headers. Use query param.

Task 5: Frontend Token Injection.

- In the API client utility (wherever fetch/axios calls are made to /api), use Clerk’s `useAuth().getToken()` to get a session token and add it as a `Bearer` token in the `Authorization` header for all REST calls.
- In the WebSocket connection hook (useMarketStream or equivalent), call `getToken()` before opening the socket and append it as `?clerk_token=<token>` to the WebSocket URL.
- On WebSocket reconnect, always fetch a fresh token before reconnecting.
- BUILD AND TEST: Confirm streaming data works when signed in. Confirm the AI strategist and all tabs function normally.
