COOLDOWN LOGIC (new feature)

This prevents the current behavior where MRVL, CRDO, and INTC get picked, fully analyzed by Claude and Gemini (burning tokens), approved, rejected by code, and then immediately picked again on the next pass in an infinite loop.

The cooldown list should be stored in memory or the database. On each pass, before the orchestrator sends tickers to the universe screener, filter out any ticker that is on cooldown.

If the cooldown list grows too large (more than 30 tickers), expire the oldest entries first.
