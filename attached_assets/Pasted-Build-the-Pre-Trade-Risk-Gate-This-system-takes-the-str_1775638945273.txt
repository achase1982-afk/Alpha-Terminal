Build the Pre-Trade Risk Gate. This system takes the strategy criteria object output by the Strategist and selects actual contracts from the live options chain, then runs a series of risk checks before presenting a concrete trade to the user. The Risk Gate is triggered when the user taps the “Check Live Pricing” button on a Strategist recommendation card. It is not automatic. The user explicitly asks for live pricing. Step 1 Chain Fetch: Using the ticker and the recommended DTE range from the Strategist criteria, fetch the live options chain from the Schwab API. Request expirations that fall within the DTE range. If no expiration falls within the range, expand by 3 days in each direction and try again. If still nothing, return an error explaining no suitable expiration exists. Step 2 Strike Selection: Using the delta targets from the Strategist criteria, find the strikes that most closely match. For a bull put spread with short strike delta 0.30, find the put with delta closest to negative 0.30. For the long strike, use the spread width from the criteria to offset. For example if spread width is 5 dollars, the long put is 5 dollars below the short put. For a bear call spread, same logic on the call side. For an iron condor, select both sides. If the exact spread width is not available due to strike spacing, use the nearest available width and note the adjustment. Always round to available strikes. Do not interpolate between strikes. Step 3 Pricing Validation: Get the live bid and ask for both legs of the spread. Calculate the natural price which is the price you would actually get filled at. For credit spreads, the natural credit is the bid of the short leg minus the ask of the long leg. For debit spreads, the natural debit is the ask of the long leg minus the bid of the short leg. Calculate the mid price as well for reference. If the bid-ask spread on either leg is wider than 20 percent of the mid price, flag the trade as having poor liquidity and warn the user. Apply tiered fill assumptions based on liquidity. If average daily volume for the specific strikes is above 1000 contracts, assume fill at mid price. If between 200 and 1000, assume fill at 25 percent between natural and mid, favoring the worse price. If below 200, assume fill at natural price only and warn the user. Step 4 Risk Calculations: Calculate maximum loss which is spread width minus credit received for credit spreads, or debit paid for debit spreads, multiplied by number of contracts multiplied by 100. Calculate maximum gain which is credit received for credit spreads, or spread width minus debit paid for debit spreads, multiplied by contracts multiplied by 100. Calculate the risk-reward ratio. Calculate the breakeven price. Calculate the return on risk as max gain divided by max loss as a percentage. Step 5 Portfolio Risk Checks: Check the current portfolio positions via Schwab API. Calculate aggregate portfolio exposure defined as total max loss across all open defined-risk positions divided by account equity. If adding this trade would push aggregate exposure above 30 percent, block the trade and explain how much room is left. Check for industry concentration. If the user already has an open position in the same GICS sector, warn but do not block. Check for directional concentration. If the user already has 3 or more positions in the same direction, warn about directional crowding. Check PDT status. If the account is under 25000 and has used 2 day trades in the last 5 business days, warn that closing this position same-day would trigger PDT. Never let PDT concerns block a risk-reducing exit though, only warn on new entries. Step 6 Pre-Submit Revalidation: This step runs only when the user decides to proceed and taps a confirm button. Right before submitting the order, fetch fresh quotes for both legs. If the credit or debit has moved more than 15 percent from what was displayed, show an updated price and ask the user to confirm again. If the spread has moved more than 30 percent, cancel the submission and show a warning that conditions have changed materially. This revalidation must complete within 5 seconds. If the API call times out, do not submit the order and tell the user to try again. On the frontend, when the user taps “Check Live Pricing” on the Strategist card, show a loading state while Steps 1 through 5 run. Display the result as an expanded trade card showing: the exact contract symbols for both legs with expiration and strike, the live bid ask and mid for each leg, the estimated fill price based on the tiered assumptions, the net credit or debit, the max loss and max gain in dollars, the return on risk percentage, the breakeven price, the number of contracts recommended, the aggregate portfolio exposure before and after this trade, any warnings from the portfolio risk checks in yellow, any hard blocks in red with explanation. Include two buttons at the bottom. One labeled “Place Order” that triggers Step 6 revalidation and then submits via the existing Schwab order placement endpoint. One labeled “Modify” that lets the user adjust strikes or contracts manually before placing. If the user taps “Place Order”, run the revalidation, show the updated price if changed, and on final confirmation submit the order through the existing portfolio.ts order placement route. Use the existing order placement and WebSocket notification pipeline. Do not create a new order submission path. If aggregate exposure would exceed 30 percent, disable the “Place Order” button and show the block reason. If the Strategist criteria included event warnings, carry them forward onto the Risk Gate card so the user still sees them. If the user came from a Micro-Override Mode 3 recommendation, verify that the scan data timestamp is still less than 5 minutes old. If stale, block and tell the user to rescan. The Risk Gate must respect Regime Shock state. If shockActive becomes true between when the Strategist ran and when the user taps “Check Live Pricing”, block the Risk Gate and explain that regime shock is now active. For error handling, if the Schwab chain API fails, show a retry button and explain the error. If a specific expiration has no available strikes near the delta target, try the next closest expiration. If the account equity call fails, block the trade since exposure cannot be calculated without knowing account size. Do not build exit order staging here. Do not build position monitoring. Do not add auto-trading or auto-execution. The user must explicitly tap “Place Order” and confirm after revalidation. That is all.​​​​​​​​​​​​​​​​
