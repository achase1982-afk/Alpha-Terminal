Build Exit Order Staging. When an order placed through Alpha Terminal is filled, detected via the ExecutionCreated event from the ACCT_ACTIVITY WebSocket, automatically stage a GTC exit order for the profit target. Take the entry credit received and the profit target percentage from the Strategist criteria which defaults to 50 percent. Calculate the limit price for the exit. For a credit spread, the exit is a buy-to-close at the target debit. For example if you received 1.50 credit and the target is 50 percent, stage a buy-to-close limit order at 0.75 debit. Submit this GTC order to Schwab immediately via the existing order placement route. Save a reference in a staged_exits table in Drizzle with the journal entry id if one exists, the Schwab entry order id, the Schwab exit order id, the exit type which is PROFIT_TARGET, the target price, and the staged timestamp. For stop losses, do NOT place a stop order with Schwab. Credit spread stop losses behave poorly as actual stop orders because of wide spreads and whipsaw during volatile moments. Instead, use an alert-based approach. Monitor the position value via the existing data streams. When the current spread value exceeds 2x the entry credit received, meaning the loss has hit the 2x stop threshold, send a push notification: “Stop alert: [TICKER] [STRATEGY] has reached 2x loss. Current value [X] vs entry credit [Y]. Consider closing.” Do not auto-close. The user decides. For time stops, track how long the position has been open relative to the DTE at entry. At 50 percent of DTE elapsed, if the position is not at 25 percent of max profit yet, send an in-app alert: “Time check: [TICKER] [STRATEGY] is at [X] percent of max profit with 50 percent of time elapsed.” At 75 percent of DTE elapsed, if profit target has not been hit, send a push notification: “Time stop approaching: [TICKER] has used 75 percent of its time. Consider managing.” At DTE minus 1 day, send a push notification: “Expiration tomorrow: [TICKER] [STRATEGY] still open. Close or roll before expiration.” Never hold through expiration is the rule. For monitoring the position value needed by the stop loss and time stop alerts, use the existing 30-second Schwab positions polling cycle. Compare the current market value of the spread legs against the entry price stored in the staged_exits table or journal. Do not create a new polling loop. When the GTC profit target exit order fills, detected via ExecutionCreated on the ACCT_ACTIVITY WebSocket, send a push notification: “Profit target hit: [TICKER] [STRATEGY] closed at [X] profit.” If the journal entry exists, auto-populate the exit price and realized P&L from the fill data. Mark the staged exit as FILLED. When the user manually closes a position either through Alpha Terminal or through TOS, the GTC exit order at Schwab may still be open. On the next polling cycle, if a position no longer exists but a staged exit order is still working, cancel the orphaned exit order via the Schwab cancel order endpoint. Log this as “Orphaned exit order cancelled: position closed externally.” Add a 2-cycle grace period before cancelling in case of partial fill timing. If an exit order is cancelled externally through TOS, detected via CancelAccepted on WebSocket, update the staged_exits record to CANCELLED and send an in-app alert: “Exit order cancelled: [TICKER] profit target removed. No automatic exit protection.” If an exit order expires, update to EXPIRED and send a push: “Exit order expired: [TICKER] profit target expired. Restage or manage manually.” If an exit order is rejected by Schwab, update to REJECTED and send a push: “Exit order rejected: [TICKER]. Check position and restage.” On the frontend, when a position has a staged exit, show it on the position card in the Portfolio tab. Display the exit type, target price, and current status of the exit order. Use a small badge or icon: green check for FILLED, yellow clock for WORKING, red X for CANCELLED or REJECTED or EXPIRED. Add a button on each position card to manually restage an exit if the original was cancelled, expired, or rejected. Add a button to modify the profit target percentage which cancels the old GTC order and places a new one at the adjusted price. Show the current P&L relative to the stop loss threshold on the position card as a simple progress indicator so the user can see how close they are to the 2x stop. Do not build auto-closing on stop loss. Do not build OCO orders. Do not build rolling functionality. Do not modify the Market Pulse engine or scanner or strategist. This is purely the exit management layer that stages exits on filled positions and monitors them with alerts. That is all.​​​​​​​​​​​​​​​​
