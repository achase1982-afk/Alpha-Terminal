# Overview

This project, "Alpha Terminal — Trading Command Center v2," is a pnpm workspace monorepo using TypeScript, designed to be an institutional-grade trading platform. It provides advanced trading tools, real-time market data, and AI-powered insights, integrating with Schwab for data and authentication. Key capabilities include advanced charting, options analysis, and AI-driven market scanning and strategy generation. The platform aims to offer a comprehensive, high-performance trading environment with a focus on data accuracy and user experience, striving for market leadership in AI-assisted trading solutions.

# System Architecture

## UI/UX Decisions

The UI features a Bloomberg/TOS-style institutional gold color palette with a dark theme (no blue shades), Inter font, and `tabular-nums`. Key components include a fixed MacroBar, a collapsible Sidebar, an Institutional Tear Sheet for detailed financials, and a ThinkorSwim-replica Options Tab with a dark gray palette, sticky headers, and configurable columns. Other UI elements are an AI Chat Overlay, Market Pulse Dashboard (SSE-streamed structured JSON with 5 fixed clusters: rates/credit/volLevel/volTermStructure/breadth, composite scoring, IF/THEN action plans, invalidation conditions, levels to watch), Market Scanner, `lightweight-charts` based Charting, a `requestAnimationFrame`-driven Ticker Tape, and CSS keyframe Price Pulse Animations. The AI tab uses iOS-style pill sub-tabs (PULSE/STRATEGIST/TECHNICALS).

## Technical Implementations

The project is a pnpm monorepo with TypeScript. The API is an Express 5 server using Zod for validation and Orval for codegen. PostgreSQL with Drizzle ORM is used for the database. Real-time streaming is handled by a singleton WebSocket client connecting to Schwab Streamer, which broadcasts live ticks to the frontend via a second WebSocket server at `/ws/prices`. On connect, the server sends a full cache snapshot; subsequent ticks arrive in real-time with zero delay. The frontend auto-reconnects with exponential backoff (1s→30s cap). Quote data flows from Schwab WS → server cache → frontend WS → Zustand stores → UI hooks. Options streaming uses volatile Zustand storage with fine-grained selectors. Connection state is managed via streamerStatus WS events with auto-recovery for token expiration.

**Dev Auth Bypass**: Setting `DEV_BYPASS_AUTH=true` (development env var) disables all Clerk auth checks without removing any Clerk code. It bypasses 3 layers: (1) Express `clerkMiddleware()` + `requireAuth()` in `app.ts`, (2) WebSocket `verifyToken()` in `wsServer.ts`, (3) Frontend `ClerkProvider`/`SignedIn`/`SignedOut` gate in `main.tsx`. The flag is passed to Vite via `VITE_DEV_BYPASS_AUTH` define. Components using `useClerk()` (`AutoLockProvider`, `Sidebar`) use a `useClerkSafe()` wrapper that returns a no-op `signOut` when bypassed. `ClerkTokenBridge` skips entirely. When `DEV_BYPASS_AUTH` is `false` or unset, all Clerk auth functions normally.

**Breadth indicators** (`$UVOL`, `$DVOL`) are not available via Schwab's LEVELONE_EQUITIES streaming. A dedicated REST poller in `schwabStreamer.ts` fetches their quotes from the Schwab REST API every 15s and injects them into the same `quoteCache` + `broadcast()` pipeline. The poller starts automatically when any WebSocket client connects and uses `market` → `trader` → module-level `accessToken` token fallback chain. A `safeNum()` filter strips Schwab's 64-bit sentinel overflow values (`>9e10`). The poller lifecycle is tied to `startStreamer()`/`addSymbols()` (start) and `stopStreamer()` (stop).

Authentication uses two layers: **Clerk** for app-level login and **Schwab OAuth 2.0** for market data APIs. Clerk auth gates the entire app via `ClerkProvider` + `SignedIn`/`SignedOut` in `main.tsx` (dark theme, `routing="hash"` for Replit URLs). The Express API uses `clerkMiddleware()` globally + `requireAuth()` on all `/api` routes (except `/api/healthz` which is public). WebSocket connections at `/api/ws/prices` require a `?clerk_token=<token>` query parameter verified server-side via standalone `verifyToken` from `@clerk/express` (NOT `createClerkClient().verifyToken`). The frontend injects Clerk Bearer tokens into all REST calls via `fetchWithAuth` and `customFetch` (both wired through `ClerkTokenBridge` in App.tsx). Schwab OAuth is a separate concern — tokens are persisted server-side in `.data/schwab-tokens.json` and auto-refreshed proactively. Schwab token storage (localStorage via Zustand persist) is untouched by Clerk auth. **Token refresh failure handling**: server-side `tokenStore.ts` detects permanent failures (`expired`, `invalid_grant`, `revoked`, `unsupported_token_type`, `failed refresh token authentication`) and clears stale tokens immediately. Frontend `PendingSessionLoader` in `App.tsx` has a 30-second cooldown guard inside `doCheck()` to prevent rapid re-fetching loops when tokens are cleared — the visibility listener is always attached regardless of cooldown state. Market News is sourced from Finnhub and Polygon.io, merged and deduplicated. An in-app article reader uses a server-side proxy to fetch and clean HTML content. Earnings dates are fetched from Yahoo Finance. AI integration defaults to `gemini-2.5-flash` (fast, ~8-15s response) with `gemini-2.5-pro` available as an option in settings. All AI streaming routes use `thinkingBudget: 2048` to cap reasoning time. Options chain data sent to the strategist is trimmed to the 3 nearest expirations × 10 ATM strikes per expiration to keep prompt size manageable. Technical analysis uses the `technicalindicators` npm package. Zustand is used for state management, with React Query for data fetching and error handling. The build system uses `esbuild` and `tsc`.

## Feature Specifications

Features include a MacroBar displaying key indices, an Institutional Tear Sheet for fundamental data, and an Options Chain with bid/ask, Greeks, configurable columns, ATM-centered strike slicing, and a MetricsStrip. The AI Strategy Endpoint generates strategies based on historical data and TA, with mandated `aiConfidence` levels. `useTickColor` provides price momentum coloring. Search History stores recent symbols. Comprehensive support for Indices & Futures is integrated across all data endpoints, including index options and futures options.

## System Design Choices

**Audit Panels**: Both Market Pulse and Options Strategist feature collapsible audit panels. The **Engine Audit Panel** (`EngineAuditPanel.tsx`) displays raw indicator values in a table (17 instruments with value/change/cluster mapping) plus per-cluster scoring rules (`rulesApplied`, `keyDataPoints`, score, data quality). Raw indicator values are passed from the SSE endpoint via `rawIndicators` field on `MarketPulseData`. The **Strategist Audit Panel** (`StrategistAuditPanel.tsx`) captures and displays all inputs fed to Gemini: underlying quote data (price, change, volume), strategy constraints (autopilot, maxRisk, minPoP, etc.), chain stats (call/put counts), and model/temperature. Audit state is cleared at run start to prevent stale display. Both panels use the gold/dark theme with `Database`/`FileText` lucide icons.

The monorepo structure facilitates shared libraries and consistent tooling. TypeScript Composite Projects ensure robust type-checking. A clear separation of concerns is maintained across UI, API, database, and streaming logic. Real-time data is optimized through streamed data with REST fallback and performant state management. Strict AI grounding is a core principle to ensure AI responses are based solely on provided, fresh market data. The Market Pulse system uses a two-layer architecture: **Layer 1** is a deterministic scoring engine (`api-server/src/lib/marketPulseEngine.ts`) — pure TypeScript math/rules, no AI — that takes 30 raw indicator values, scores 5 clusters (rates, credit, volLevel, volTermStructure, breadth) from -2 to +2, calculates weighted composite, determines bias with hysteresis, and outputs deterministic JSON. Same input ALWAYS produces same scores. **Layer 2** is Gemini (temperature=0) which receives the pre-calculated scores + raw data and writes ONLY the narrative (synthesis, action plan, invalidation conditions) — it CANNOT change any scores/labels. The SSE streaming endpoint at `/api/ai/market-pulse/stream` runs the engine first, streams thinking tokens, then merges engine output + Gemini narrative into the final result. If narrative parsing fails, engine scores are still sent as a fallback. The frontend sends `previousBias` with each request for hysteresis (preventing label flickering on tiny score changes). Each cluster includes a `rulesApplied` array showing exactly which threshold rules fired. Components live in `components/market-pulse/` (NOT `components/pulse/` which has been removed). The `useAiStream` hook in `hooks/useAiStream.ts` handles SSE consumption. The bias strip (`AiBiasStrip`) is a 36px-tall dark muted status bar (bg-zinc-900/80) with bias-colored text accents and 3 confidence dots; sticky layout cascade is AiBiasStrip=36px(top:0) → MetricsBar=36px(top:36) → primary nav(top:72). It navigates to AI→PULSE sub-tab when tapped. Market Pulse always uses `gemini-2.5-pro` at temperature=0 (hardwired, ignores sidebar model selector). Confidence formula v2 uses 7 factors: freshness, weighted participation, boundary proximity, signal magnitude, dispersion, volatility regime cap, and extreme disagreement. SPY divergence is injected into the Gemini prompt when macro bias disagrees with SPY price direction. Market Pulse settings (auto-refresh, display preferences, indicator management with per-category toggling and bulk select/deselect, allowed strategies checklist, spread width, account size tier, preferred tickers, max risk per trade) are persisted in the Zustand store with version migration. The `pulseIndicators` array in `MarketPulseSettings` controls which symbols are sent to the engine — organized into 6 categories (volatility, breadth, rates, credit, equity futures, commodities) with 30 indicators total. The indicator catalog lives in `ALL_PULSE_INDICATORS` in `types/marketPulse.ts`. The store migrates older persisted state (v0→v1) to include `pulseIndicators` automatically.
